# S00 — Plan scaffolding and the status tool

**Phase A** · depends on: nothing · **this step is the one you are reading**

## Purpose

Put a resumable, self-verifying work queue in the repository so that a session with no
memory of prior work can determine the current state by running one command.

## Capability declaration

```yaml
name: plan-status
purpose: Report the first incomplete planned step by running each step's acceptance check.
input_schema: docs/plan/queue.json (schema_version "1")
output_schema: human summary, or --json payload with next_step and per-step outcome
reads: docs/plan/queue.json; the test suite; declared artefact paths
writes: nothing outside stdout
forbidden_paths: src/archiv/** (this step adds no product behaviour)
network_policy: none
timeout_policy: bounded by one pytest invocation over the declared targets
evidence_produced: tests/test_plan_status.py
validator: tests/test_plan_status.py — including a test that a regression in a completed
  step moves the reported next step backwards
```

## What to build

- `CLAUDE.md` at the repository root — the auto-read entry point. Short: resume
  procedure, setup, the check commands, the hard rules, an orientation table.
- `docs/plan/README.md` — how the queue works and why.
- `docs/plan/queue.json` — the single source of truth.
- `docs/plan/QUEUE.md` — human-readable view of the same data.
- `docs/plan/steps/S00.md … S27.md` — Phase A in full, later phases as stubs.
- `docs/plan/DECISIONS.md`, `docs/plan/TRAPS.md`.
- `scripts/plan_status.py`.
- `tests/test_plan_status.py`.
- A link from the documentation index in `README.md:552-595`.

## Reuse rather than reinvent

- `scripts/audit_ci_trust.py` + `tests/test_github_governance.py` is the existing
  tool-plus-test-of-the-tool pattern. Follow it: the guardrail gets its own proof that it
  actually enforces something, not merely that the current tree happens to pass.
- `tests/privacy_scan_support.py` states the principle explicitly in its docstring —
  worth reading before writing `tests/test_plan_status.py`.
- `docs/format-compatibility.json` ↔ the README table ↔ `tests/test_format_matrix.py` is
  the existing "machine-readable source of truth with a test that the prose agrees"
  pattern. `queue.json` ↔ `QUEUE.md` follows it.

## Acceptance

```
tests/test_plan_status.py::test_queue_json_matches_queue_markdown
tests/test_plan_status.py::test_status_tool_reports_first_incomplete_step
tests/test_plan_status.py::test_status_tool_detects_regression_in_a_completed_step
tests/test_plan_status.py::test_every_step_has_a_doc_and_a_declared_acceptance_check
```

The third test is the important one: build a temporary queue whose first step passes and
whose second fails, assert the tool names the second; then break the first and assert the
tool names the *first*. A queue that cannot detect regression is not self-verifying.

## Notes

`scripts/` is outside `pyright`'s `include` list (`pyproject.toml` sets
`include = ["src", "tests"]`), so the script is not strict-type-checked, but it is still
subject to `ruff format` and `ruff check` at line-length 100. `tests/` **is** strictly
type-checked — every test needs `-> None` and `from __future__ import annotations`.
