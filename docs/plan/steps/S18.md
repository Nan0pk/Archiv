# S18 — OpenDocument to OOXML parity fixtures and format-matrix update

**Phase C** (Recover the content being silently dropped) · depends on: S17

## Why this step exists

The strongest available acceptance test for phase C is cheap to maintain: build each
OOXML fixture with an OpenDocument twin carrying the same content, then assert that both
produce the same recoverable text and tables. A divergence then shows up as a failed test
instead of as silence in one reader.

The stub for this step said the OpenDocument reader was "already correct". It is correct
for paragraphs, headings, spreadsheet cells and slide object text, but it is not at
parity with the recovery S15–S17 added:

- **Text.** `normalize_odf.py` iterates every `text:p` in the body, including paragraphs
  inside `table:table`. Table text is therefore indexed as ordinary paragraphs; no
  `NormalizedTable` is produced and no `table`/`row`/`column` locator exists, although
  the matrix claims `tables` under `structure`.
- **Spreadsheet.** Cells, formulas and stored values are read. Merged and hidden state
  and hyperlinks are not.
- **Presentation.** `_page_segments` emits one `object` segment per page child. It skips
  `presentation:notes` outright, and a `draw:frame/table:table` is flattened into one
  object segment instead of being read as a table.

This step builds the parity fixtures and fixes the reader where content is lost or
unstructured: text tables, presentation tables and presentation speaker notes. It also
makes the OpenDocument rows of the matrix say what is actually true. The remaining
parity work — hyperlinks, footnotes and endnotes, merged and hidden spreadsheet state,
charts, grouped shapes, hidden slides/shapes and placeholder roles — is step S18A, added
to the queue by this change. Claiming it here would repeat the stub's mistake of
describing a reader that does not exist yet.

## Capability declaration

```yaml
name: opendocument-ooxml-parity
purpose: >
  Prove that an OpenDocument twin and its OOXML original yield the same recoverable
  content for text tables, spreadsheet cell values and stored formula results, and
  presentation tables and speaker notes; read tables on drawing pages through the same
  page reader; and make the published OpenDocument matrix describe the readers
  truthfully.
input_schema: >
  A canonical .odt/.ods/.odp original, or one of its template or flat-XML variants, and
  the generated OOXML twin carrying the same content.
output_schema: >
  A NormalizedDocument for each side. Parity is compared as ordered segment text and
  ordered table row values, not as identical locator key names: the two families use
  different locator vocabularies by design.
reads: >
  The original's content.xml and, where the claimed content needs it, its
  META-INF/manifest.xml. No network access, and no part outside the package is read.
writes: derived/** only, through the existing normalization path
forbidden_paths: objects/** (originals are never modified), config/**, runs/**
network_policy: none; external links are counted and ignored, never fetched
timeout_policy: >
  The existing ODF limits apply unchanged: package, member and total uncompressed size
  limits, archive-entry limit, compression-ratio limit, XML-node limit, expanded
  row/cell limits and the segment character limit. The new table walks reuse the
  spreadsheet limits and do not add an unbounded traversal.
evidence_produced: >
  tests/test_ooxml_odf_parity.py (three acceptance tests plus failure-state and
  end-to-end tests) and the live-ingestion matrix test in tests/test_format_matrix.py.
validator: pytest acceptance targets below
```

## Decisions made in this step

- **Parity is content parity.** Each twin pair is normalized through the real ingestion
  path, and the tests compare the ordered text of all segments and the ordered values of
  every `NormalizedTable`. Locator key names are not compared across families; comparing
  `cell`/`sheet` with `column`/`row`/`sheet` would demand a breaking relabelling that the
  plan does not ask for and that would invalidate existing citations.
- **Text tables.** A top-level `table:table` in a text document yields one segment per
  non-empty cell, located by `table`, `row` and `column` (all 1-based), plus a
  `NormalizedTable` at `{"table": number}`. Paragraphs inside table cells are not also
  emitted as ordinary paragraph segments, so the same text is not indexed twice. A
  `table:covered-table-cell` carries no text of its own and yields nothing. A table
  nested inside a cell is refused rather than flattened into the outer cell.
- **Presentation tables.** A `draw:frame/table:table` yields one segment per non-empty
  cell, located by `slide`, `object`, `row` and `column` (1-based), plus a
  `NormalizedTable` at `{slide, object}`. `object` remains the page child's 1-based
  position, so existing object locators keep their meaning; the table adds row and
  column. A covered cell yields nothing.
- **Drawing pages reuse the page reader.** A table inside a `draw:frame` on a drawing
  page is read the same way, located by `page`, `object`, `row` and `column`. A drawing
  has no OOXML twin, so the parity tests cannot compare it; a direct test pins the
  drawing locator.
- **Speaker notes.** Each `presentation:notes` page yields one segment per text-bearing
  top-level frame, located by `slide` and `speaker_notes` = 1, 2 and so on in order.
  The notes page's slide image, page number, date/time, header and footer placeholders
  are skipped by their `presentation:class`. Only top-level text frames on the notes
  page are read; a group or table there is not read, and a hidden shape there is not
  marked. This is recorded in `docs/known-issues.md`.
- **Spreadsheet values are pinned, not reimplemented.** `_cell_value` already prefers the
  displayed text and falls back to `office:value`, so a formula with a stored result
  yields that result and carries its expression in `formula`. The parity test pins this
  against the XLSX reader. Merged and hidden state and hyperlinks are not claimed here.
- **The ODF processor version moves from 3 to 4**, because text tables, presentation
  tables and speaker notes change the produced document. As with the OOXML readers,
  existing derivatives are not rebuilt automatically; `archiv rebuild-derived` changes
  the derived hash, and earlier citations for that document fail closed.

## Not in this step

Recorded in the OpenDocument `known_limits` and queued as S18A:

- text hyperlink targets and footnote or endnote structure; their text remains inline
  in the paragraph;
- spreadsheet hyperlink targets, merged-range state, and hidden sheet, row and column
  markers; cell values are still read;
- presentation charts, grouped shapes, hidden slides and shapes, and placeholder roles.

Hyperlink targets, alternative text, SmartArt, embedded objects and comments remain
outside the OpenDocument surface, as they are for the corresponding OOXML readers where
recorded.

## Acceptance

```
tests/test_ooxml_odf_parity.py::test_equivalent_documents_yield_equivalent_recovery
tests/test_ooxml_odf_parity.py::test_equivalent_workbooks_yield_equivalent_recovery
tests/test_ooxml_odf_parity.py::test_equivalent_presentations_yield_equivalent_recovery
tests/test_format_matrix.py::test_matrix_matches_live_ingestion
```

The parity file also holds structural and failure-state tests: a text table nested
inside another table is refused; a text table that exceeds the expanded row budget is
refused; a table cell whose joined text exceeds the segment character limit is refused;
a text table's header and row-group wrappers are read in document order; a drawing page
table is read with its `page` locator; a drawing frame keeps its caption text beside
the table; a footnote in a table cell is included once; a presentation table with
inconsistent row widths is padded to its widest row, as the PowerPoint reader pads its
own; a notes page with only furniture yields no notes segments; and a table cell is
found by `archiv search` in both families with its slide or table and its row and
column.
