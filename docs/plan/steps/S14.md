## Why this step exists

Three separate honesty gaps, all cheap.

**`doctor` did not check what the commands need.** The install flow ends with *"Then
confirm it worked: `archiv doctor`"*, and doctor checked Python, an FTS5 round-trip and a
writable temp directory only. It did not probe LibreOffice (needed by `report`), Tesseract
(OCR), or tkinter (`ui`) — the three the README's own prerequisites table (`README.md`,
"Before you install") already calls out. A user with none of them installed got a clean
bill of health and then a runtime failure. These are advisory, not pass/fail: a missing
optional dependency narrows what the install can do, it does not make the deterministic
minimum broken, so `archiv doctor --json` must keep exiting 0 in CI, which has none of the
three, exactly as it did before this step.

**Five commands were undocumented, and more were hiding behind them.** `who`, `images`,
`faces`, `graph`, and `process` were registered in the CLI and absent from every README
command table, which is prefaced *"Every row below is implemented and tested — not
planned."* Walking the actual Typer command tree (not just grepping for a few names)
found six more: `model configure-loopback`, `model profiles`, `model calibrate`, and the
whole `model spend` group were also undocumented. A test that walks the registered
command tree and asserts every leaf appears in the README makes the whole class of drift
impossible to repeat, not just the five instances already found.

**The expansion plan claimed completion it did not have.** `docs/capability-expansion-plan.md`
carried "Status: Implemented ... verified with comprehensive acceptance tests" against
milestones whose own specified measurements were never produced — the exact failure
`CLAUDE.md` names under **Evidence**, tracked as an open item in `docs/known-issues.md`
until this step. The blockquote and the sentence after the milestone table are corrected
to say plainly what shipped versus what was verified, and a script now fails a documented
completion claim that has no test path, script, or measured-report reference next to it.
Also corrected: `docs/public-repository-policy.md` said no licence had been selected,
contradicting `CONTRIBUTING.md`, `pyproject.toml`, and the recorded decision at
`docs/decisions/license-apache-2-0.md`, all of which already say Apache-2.0.

## Acceptance

The queue's existing draft targets are confirmed unchanged:

```
tests/test_doctor_optional_dependencies.py::test_doctor_reports_libreoffice_tesseract_and_tkinter
tests/test_doctor_optional_dependencies.py::test_advisory_rows_name_the_command_they_unblock
tests/test_documentation_coverage.py::test_every_registered_cli_command_appears_in_the_readme
tests/test_documentation_coverage.py::test_no_plan_status_line_claims_done_without_its_artefact
```

The first test proves `doctor_report()` names all three optional dependencies with their
actual availability, using `monkeypatch` so the result does not depend on what happens to
be installed on the machine running the suite.

The second test proves each advisory row names the concrete command it would degrade, not
a generic "install this" message.

The third test walks the Typer command tree via `typer.main.get_command` and asserts every
leaf command path (including nested groups like `model spend status`) appears in
`README.md`, so a future command can no longer ship undocumented.

The fourth test runs `scripts/audit_status_claims.py` against the real repository and
asserts zero violations, plus fixture-backed cases proving the auditor both rejects an
unbacked completion claim and accepts one with a test path next to it.

## Must not change

- Do not make any of the three new advisories affect `doctor`'s overall `status`; CI has
  none of LibreOffice, Tesseract, or tkinter installed and `archiv doctor --json` must
  keep exiting 0.
- Do not rewrite the substance of `docs/capability-expansion-plan.md` beyond its
  completion claims — the rest of the document's technical content is a separate,
  unaudited concern recorded in `docs/known-issues.md`.
- Do not implement S15–S27 in this step.
- Do not touch originals, derived data, or any model call.
