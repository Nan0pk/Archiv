## Why this step exists

Three separate honesty gaps, all cheap.

**`doctor` does not check what the commands need.** The install flow ends with *"Then
confirm it worked: `archiv doctor`"*, and doctor checks Python, an FTS5 round-trip and a
writable temp directory. It does not probe LibreOffice (needed by `report`), Tesseract
(OCR), or tkinter (`ui`) — the three the README's own prerequisites table calls out. So a
user with none of them installed gets a clean bill of health and then a runtime failure.
The desktop UI already probes all three; the CLI does not.

**Five commands are undocumented.** `who`, `images`, `faces`, `graph` and `process` are
registered in `cli.py` and absent from both README command tables — tables prefaced
*"Every row below is implemented and tested — not planned."* A test that asserts every
registered command appears in the README makes this class of drift impossible to repeat.

**The expansion plan claims completion it does not have.** Correct the status lines, and
add the CI check that refuses a status-line edit without its acceptance artefact in the
same diff. Also: `docs/public-repository-policy.md` still says no licence has been
selected, contradicting `CONTRIBUTING.md` and `pyproject.toml`, which are Apache-2.0.
