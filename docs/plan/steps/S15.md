# S15 — DOCX: tables, headers, footers, footnotes, comments, hyperlinks, headings

**Phase C** (Recover the content being silently dropped) · depends on: S00

## Why this step exists

Reproduced on `d9a9b8d`: a Word document containing one paragraph, a 2x2 table
of names and dates, and a footer yielded **one segment** — the paragraph. The table and
footer were dropped entirely.

The cause is that `python-docx`'s `document.paragraphs` does not include paragraphs
inside tables; cell text lives in `document.tables[*].rows[*].cells[*].paragraphs`. So a
Word document whose content *is* a table yields nothing at all. Headers, footers,
footnotes, endnotes and comments are separate parts of the package and were never read.
Hyperlink targets live in the package's relationships, not in the text, so only the
visible link text survived. Heading paragraphs were indistinguishable from body text.

`normalize_odf.py` handles the OpenDocument equivalent, so there is a working reference
in this repository. S18 turns that into a parity test.

## Capability declaration

```yaml

purpose: >
  Surface every piece of text a Word document stores in its body tables, headers,
  footers, footnotes, endnotes and comments, plus hyperlink targets and heading levels,
  each with a locator that says where it came from, so it can be searched and cited.
input_schema: a canonical .docx original that python-docx can open
output_schema: >
  NormalizedDocument with segments and tables. Locator shapes are listed for the
  office-word family in docs/format-compatibility.json.
reads: the original's package parts (document, headers, footers, footnotes, endnotes,
  comments, styles, relationships)
writes: derived/** only, through the existing normalization path
forbidden_paths: objects/** (originals are never modified), config/**, runs/**
network_policy: none; hyperlink targets are recorded as text and never fetched
timeout_policy: bounded by the ingestion size limit and by ceilings in
  src/archiv/ingestion/normalize_docx.py, all checked before any original is stored.
  MAX_TABLE_CELLS counts table grid positions (spans, leading gaps and row padding
  included, not only cells); MAX_TABLE_COLUMNS caps any one row; MAX_XML_NODES caps
  each parsed part; and any part declaring a DTD or entity is refused outright

  docs/format-compatibility.json checked against live ingestion by
  tests/test_format_matrix.py
validator: pytest acceptance targets below
```

## Decisions made in this step

- **Body paragraph numbering does not change.** `paragraph` stays the 1-based position
  among paragraphs directly in the body, counting empty ones, and body text follows the
  exact rules `python-docx` uses for `Paragraph.text`, so "paragraph N" still names the
  same text it did before. A test pins this against `python-docx`. That does **not** keep
  saved citations valid: a saved citation also records the whole derived document's hash
  and the segment's position, so once a document is rebuilt with this reader, citations
  already saved for it stop validating. They fail closed rather than point at the wrong
  text.
- **Headings keep their paragraph number** and gain `heading_level`, rather than being
  renumbered on a separate counter the way `normalize_odf.py` does. Renumbering would
  break existing body citations. S18 decides how the two formats are compared.
- **Tables** are numbered in document order within their story (body, a header, a
  footnote...). Each non-empty cell is one segment located by `table`, `row` and grid
  `column`. A horizontally merged cell is located at its first column; cells covered by
  a vertical merge carry no text and yield nothing. A table nested in a cell is folded
  into that cell's text, so none of its words are dropped.
- **Headers and footers** are located by `section` and `header`/`footer` =
  `default`/`first`/`even`. A header linked to the previous section has no content of its
  own and is not repeated.
- **Footnotes, endnotes and comments** are located by the `w:id` stored in the file.
  Word's separator entries are skipped.
- **Hyperlink targets** are separate segments whose text is the target, located by the
  paragraph or cell locator plus `hyperlink` = its 1-based position there. Internal links
  are written as `#bookmark`. A link whose relationship is missing is skipped, not guessed.
- The `docx` extractor version moves from 1 to 2.

## Not in this step

Recorded in the office-word `known_limits`: tracked-change text, content controls and
field codes (including `HYPERLINK` field codes; a table row wrapped in a content control
is skipped and row numbers pass over it), and text boxes and shapes. Documents added
before this change keep their older derivative until `archiv rebuild-derived` is run for
them; nothing rebuilds them automatically, and rebuilding one makes the citations already
saved for it stop validating.

Heading levels come from a paragraph's own outline level or from a built-in "Heading N"
style it names directly. A level set inside a style's definition, or a custom style
based on a heading style, is not detected.

The file also holds failure-state and end-to-end tests: nested tables and vertical
merges, a hyperlink with a missing relationship, an invalid grid span, a wide span that
exhausts the grid budget, a span past the column ceiling, an entity declaration in the
footnotes part, a malformed note identifier kept rather than refused, outline level 9
overriding a heading style, and a table cell found by `archiv search` with its table
locator.
