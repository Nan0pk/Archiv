## Why this step exists

Reproduced on `d9a9b8d`: a Word document containing one paragraph, a 2x2 table
of names and dates, and a footer yielded **one segment** — the paragraph. The table and
footer were dropped entirely.

The cause is that `python-docx`'s `document.paragraphs` does not include paragraphs
inside tables; cell text lives in `document.tables[*].rows[*].cells[*].paragraphs`. So a
Word document whose content *is* a table yields nothing at all.

`normalize_odf.py` handles the OpenDocument equivalent correctly, so there is a working
reference implementation in this repository. S18 turns that into a parity test.
