# S11 — Faces to clustering only; remove filename name guessing; add negative fixtures

**Phase B** (Stop the tool overclaiming) · depends on: S10B

## Capability declaration

```yaml
name: faces-clustering-only
purpose: Keep the opt-in face-clustering and confirmation workflow while removing identity guesses and preventing the known non-face false positives until S24 supplies a real detector.
input_schema: Opted-in Archiv image objects and existing face-cluster records.
output_schema: Unconfirmed face clusters and user-confirmed labels; no automatically proposed person names.
reads: Canonical image originals, face opt-in configuration, derived image metadata, and the face index.
writes: Rebuildable face detections, embeddings, clusters, and explicit user confirmations only.
forbidden_paths: Canonical originals, filename-derived identity hypotheses, guessed confidence values presented as identity evidence, and any weakening of the face opt-in gate.
network_policy: No network access. No model or weight download at runtime.
timeout_policy: Existing bounded ingestion and face-processing limits remain unchanged.
evidence_produced: Generated negative fixtures plus face-index and command output exercised by the acceptance tests.
validator: The two S11 pytest acceptance targets declared in docs/plan/queue.json.
```

## Why this step exists

The current face detector is `_is_skin_tone(r, g, b)` plus connected components on a
128x128 downsample, filtered by aspect ratio and bounding-box fill. It can file a tan
ellipse as `Person 1`. The attribution layer can then turn the filename into a candidate
person name and assign a computed confidence. Neither is adequate evidence for a claim
about a person's identity.

Decision 5 in [`../DECISIONS.md`](../DECISIONS.md) settles the product behaviour for this
step: until S24 lands a real detector, faces is clustering-only and proposes no names.
Filename-derived names are removed entirely. The privacy scaffolding stays: opt-in gating,
`Unconfirmed` status, first-class erasure, and explicit user confirmation.

This step does not try to build the S24 detector early. It removes the unsafe claims from
the current surface and adds generated negative fixtures for the concrete false-positive
class that exposed the problem. S24 reuses those fixtures when the real detector lands.

## Required behaviour

- No filename, path component, stem, or extension may become a candidate person name.
- `faces who` may show cluster identity, membership and an explicit user-confirmed label,
  but it must not propose an automatically inferred person name before S24.
- A vase, wooden table, sunset and brick wall generated by the test suite must produce no
  face detections.
- Existing opt-in checks, erasure behaviour and user confirmation remain in force.
- Generated fixtures stay in temporary test directories; no binary fixture is committed.
- No new default dependency and no runtime download are introduced.

## Writes

Keep the implementation bounded to the face subsystem and its tests. Expected files are:

- `src/archiv/faces/detector.py` only as needed to make the declared negative fixtures
  refuse non-faces without pretending the heuristic is a real detector;
- `src/archiv/faces/attributions.py` and, if necessary, `src/archiv/faces/cli.py` to remove
  automatic name proposals while preserving explicit confirmations;
- `tests/test_faces_negative_fixtures.py` for generated negative images and filename
  attribution regression coverage.

Do not widen this step into S24, change the model/privacy boundary, or alter unrelated
image-similarity behaviour.

## Acceptance

The provisional targets are confirmed unchanged and remain authoritative in

```text
tests/test_faces_negative_fixtures.py::test_no_detections_on_vase_table_sunset_or_wall
tests/test_faces_negative_fixtures.py::test_no_name_candidate_is_ever_derived_from_a_filename
```

Both must pass. The full repository checks in `CLAUDE.md` must also pass before the pull
request is eligible for independent review and merge.

## Failure and skip rules

A non-face fixture producing even one detection is a failure, not an expected heuristic
limitation. A filename producing any candidate identity is a failure. Missing optional
face tooling may be reported as unavailable only where an existing test explicitly models
that optional dependency; it must not turn either S11 acceptance target into a silent
pass.
