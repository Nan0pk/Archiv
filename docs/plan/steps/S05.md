# S05 — Stamp the ask path with model origin

**Phase A** · depends on: S04

## Purpose

Make it impossible for a remote-model answer to be mistaken for a local one, anywhere the
`ask` path produces output.

## The good news

`AskRunResult.model` embeds the **whole** `ModelConfig` (`ask_contracts.py:27`). So once
S02 added `provenance`, it already propagates automatically into:

- every `runs/ask/<run_id>/result.json` — written at all six terminal branches
  (`grounding.py:161, 203, 220, 251, 272, 286`);
- `runs/ask/<run_id>/request.json` (`grounding.py:224-234`);
- `archiv ask --json` output (`user_cli.py:508`);
- the `archiv status` payload (`user_cli.py:336`).

Verify that rather than re-implementing it. The work in this step is the surfaces that
*do not* get it for free.

## Capability declaration

```yaml
name: ask-provenance-stamp
purpose: Ensure every ask artefact and every human-visible answer states the model origin.
input_schema: ModelConfig with a provenance field
output_schema: AskRunResult (unchanged shape; provenance rides inside model)
reads: config/model.json
writes: runs/ask/<run_id>/*
forbidden_paths: originals/**
network_policy: inherited from the configured adapter
timeout_policy: inherited
evidence_produced: runs/ask/<run_id>/result.json carrying provenance
validator: tests/test_remote_evaluation_provenance.py
```

## What to change

- `user_cli.py:564-565` currently prints `Model: {adapter} ({model or adapter})`. For a
  remote run it must state plainly, **above** the answer rather than after it, that the
  answer was produced by a non-local model and the documents in this archive were sent
  off the machine. Below the answer is too late to be a warning.
- Check the failure branches. A `blocked_by_policy` ask prints only the error string
  today (`user_cli.py:513-516`), so the S04 refusal message has to be self-explanatory on
  its own.
- The desktop UI builds `["ask", q, "--home", …, "--json"]` (`ui/product.py:167-170`) and
  `ui/outputs.py` never reads `result["model"]`. Either surface the stamp there too or
  record the gap in `docs/known-issues.md` — do not leave it undecided.

## Acceptance

```
tests/test_remote_evaluation_provenance.py::test_ask_result_json_records_remote_provenance
tests/test_remote_evaluation_provenance.py::test_ask_human_output_states_the_answer_is_not_local
tests/test_remote_evaluation_provenance.py::test_no_remote_ask_can_produce_an_unstamped_result
```

The third test should enumerate all six terminal branches in `run_grounded_ask` and
assert the stamp on each — including the two that never call the model
(`grounding.py:152-162` policy block, and `:206-221` which succeeds with no evidence and
therefore no model call at all).
