# S05A — Every ask that calls a model records that it did

**Phase A** · depends on: S05

> Added after review, not in the original plan. The reviewing agent found it while
> checking a sentence written to correct an earlier false claim — the sentence said this
> gap did not exist.

## The gap, reproduced

An `ask` run that reaches the model and then fails to write its own evidence escapes
`run_grounded_ask` entirely. No `AskRunResult` is built, so no `result.json` is written,
and because the terminal banner is driven by the returned result, nothing tells the user
anything happened.

Three writes sit after `adapter.complete` has returned and outside every guard:
`model_response.txt` (`grounding.py:312`) and the two `result.json` writes
(`:329`, `:343`).

Reproduced by simulating a full disk at the first of them:

```
ESCAPED: OSError [Errno 28] No space left on device
model was called: 1 time(s)
run dir has NO result.json; contains ['request.json', 'retrieval.json', 'structured_output.json']
```

The archive's text went to the remote service. The user saw
`ask failed: OSError: [Errno 28] No space left on device` and no evaluation-mode warning
at all.

## Why it matters more than its likelihood

It needs a filesystem failure inside a one-line window, so it is unlikely. But S05 exists
so that no answer produced outside this machine can be mistaken for a local one, and this
is the one path where documents provably left and the run said nothing. An unlikely
unreported disclosure is still an unreported disclosure, and `runs/` is classified in
`docs/architecture.md` as terminal append-only evidence — a run directory with no result
in it is a hole in that contract as well.

Two smaller escapes belong to the same shape and should be handled together: the
empty-query raise (`grounding.py:167-168`), and retrieval and citation validation
(`:209`, `:221`, `:228`). Those three precede the prompt, so nothing was sent — they are
not disclosures, only missing evidence.

## Capability declaration

```yaml
name: ask-terminal-evidence
purpose: Guarantee that every ask which called a model leaves a stamped run result,
  including when writing that result is what failed.
input_schema: none (existing ask inputs)
output_schema: AskRunResult on every path that reaches the model
reads: config/model.json
writes: runs/ask/<run_id>/*
forbidden_paths: originals/**, derived/**
network_policy: unchanged
timeout_policy: unchanged
evidence_produced: runs/ask/<run_id>/result.json on every model-calling path
validator: tests/test_ask_terminal_evidence.py
```

## What to change

- Bring everything after the model call inside the guard that already exists, so a write
  failure produces a `failed` result carrying the model config rather than escaping.
- The last-resort case needs thought rather than a wrapper: if writing `result.json` is
  itself what failed, a handler that writes `result.json` fails too. Decide what the
  contract is when evidence cannot be written at all — the honest options are to surface
  it loudly in the exit message including the provenance, or to write a minimal record by
  a different route. Do not pretend the write succeeded.
- Whatever is chosen, the human-visible failure for an evaluation archive must still say
  the archive reaches outside this machine.

Simulate the write failure; do not fill a disk. No test may make a network call.
