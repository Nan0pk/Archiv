## Why this step exists

Replace the heuristic with YuNet, as `docs/capability-expansion-plan.md`
originally specified. It is an ONNX model, so it runs on the `onnxruntime` this project
already pins in its `ocr-benchmark` extra — no new inference stack.

Weights are a pinned installed artefact with a recorded SHA-256, never fetched at
runtime, recording `skipped` when absent.

**Research resolved the recognition-weights question, and it is better news than the
expansion plan assumed.** YuNet detection is **MIT** (opencv_zoo) and **SFace** face
recognition is **Apache-2.0** — a genuinely permissive embedding model, reported at
0.9940 accuracy on the zoo's benchmark, with a cosine verification threshold around
0.363. LocalAI ships exactly this pairing labelled "commercial-safe". So clustering-only
is no longer the forced fallback: **YuNet + SFace** is the target.

**The trap, stated plainly: InsightFace's MIT badge is a decoy.** Its code is MIT but its
pretrained packs (`buffalo_l`, `antelopev2`, `w600k_r50.onnx`) are licensed for
**non-commercial research only**, and they sell enterprise licences for exactly those.
This has publicly bitten other projects. Treat any InsightFace pretrained pack as
unusable here regardless of the repository badge. AuraFace-v1 is the intended permissive
alternative but its licence tag could not be verified first-party during research —
confirm on the model card before adopting.

**Therefore add a dependency check that records code licence and weights licence as
separate fields.** Every trap in this area lives in the gap between those two.

`.gitignore` already blocks `*.onnx`, `*.gguf`, `*.safetensors` and `models/`, so weights
cannot be committed by accident.
