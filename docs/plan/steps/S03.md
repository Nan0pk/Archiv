# S03 — Evaluation-only archive marker with a raising opt-in check

**Phase A** · depends on: S02

## Purpose

Give an archive a durable, explicit mark saying "this one is for evaluation, documents in
it may be sent to a remote model". Without the mark, the remote adapter refuses. This is
what keeps the remote path away from real documents.

## Copy the existing precedent exactly

`src/archiv/faces/config.py` is already this pattern, built for biometric opt-in, and it
is the right shape:

| Piece | Where | Behaviour to mirror |
|---|---|---|
| Config model | `faces/contracts.py:10-16` | `opt_in: bool`, `opt_in_at: str \| None` |
| Loader | `faces/config.py:23-40` | **Missing file means not opted in.** Env override. **Corrupt file fails closed to not-opted-in**, never raises out |
| Saver | `faces/config.py:43-48` | atomic write into `config/` |
| Gate | `faces/config.py:51-59` | raises a typed error whose message **names the exact command to run** |

Do not invent a new mechanism. A second `config/<feature>.json` is exactly how this
project does per-archive feature state — there is no layout-level flags file, and
adding one is out of scope.

## Capability declaration

```yaml
name: evaluation-archive-marker
purpose: Record and enforce explicit consent for an archive to be used with a remote model.
input_schema: config/evaluation.json — {schema_version, evaluation: bool, acknowledged_at, acknowledgement}
output_schema: same
reads: config/evaluation.json
writes: config/evaluation.json
forbidden_paths: originals/**, derived/**, indexes/**
network_policy: none
timeout_policy: n/a
evidence_produced: config/evaluation.json with an acknowledgement timestamp
validator: tests/test_evaluation_marker.py
```

## What to build

- `src/archiv/evaluation_config.py` (or `evaluation/config.py` if it grows) with
  `load_evaluation_config`, `save_evaluation_config`, and
  `check_evaluation_opt_in(home) -> None` raising a typed
  `EvaluationNotEnabledError`.
- The stored record must include a UTC `acknowledged_at` and the acknowledgement text the
  user agreed to, so consent is auditable rather than a bare boolean.
- CLI: extend the `model` sub-app (`model_cli.py`, registered at `cli.py:34`) with a way
  to set and show the marker. Setting it requires an explicit acknowledgement flag —
  never a bare `--yes`.
- An env override for tests, following `ARCHIV_FACES_OPT_IN` (`faces/config.py:29-31`).

## Wording matters here

The error message is the whole user experience of this feature. `faces/config.py:51-59`
sets the bar — it says what is disabled, why, and the exact command to enable it. This
one additionally has to say plainly that enabling it means documents leave the machine.

## Note

`config/` is in `DURABLE_DIRECTORIES` (`archive.py:25`) and is included in backups,
exports and restores (`archive.py:96, 127, 173`). So the evaluation mark travels with a
backup — which is correct (an evaluation archive stays an evaluation archive when
restored) but should be stated in the step's PR and in the user-facing docs.
