# S14A — Type-check the scripts that CI actually runs

**Phase B** · depends on: S14

> Added after review. Found because a change made a required parameter and the type
> checker reported clean while a script CI runs was left calling the old signature.

## The gap

`pyproject.toml` sets pyright's `include = ["src", "tests"]` and
`extraPaths = ["scripts"]`. So `scripts/` is importable by the type checker but never
checked by it.

That is not a theoretical hole. `scripts/build_office_validation_artifacts.py` is invoked
by `.github/workflows/office-validation.yml`, which runs on any change under `src/**`.
When `generate_report` gained two required parameters, that script kept calling the old
signature; every local check passed, and the failure would only have appeared in a job
that cannot be run in the standard container because it needs LibreOffice and Poppler.

The same applies to every other script CI or a contributor runs. `scripts/` currently
holds the fixture-corpus generator, the plan status tool, the trust auditor and the
office-artifact builder, all of which are load-bearing and none of which are type
checked.

## Capability declaration

```yaml
name: script-type-coverage
purpose: Bring the scripts CI executes under the same type checking as src and tests.
input_schema: none
output_schema: none
reads: pyproject.toml; scripts/**
writes: pyproject.toml; scripts/** as needed to pass
forbidden_paths: originals/**, derived/**
network_policy: none
timeout_policy: n/a
evidence_produced: pyright clean with scripts included
validator: pyright, plus a test asserting the include list covers what CI runs
```

## What to change

- Add `scripts` to pyright's `include`, and fix whatever that surfaces.
- Add a check that the include list actually covers every script referenced from
  `.github/workflows/**`. Doing it by hand once fixes today; a check fixes the next
  script somebody adds. `tests/test_github_governance.py` already parses the workflow
  files and is the natural home.

## Acceptance

```
tests/test_github_governance.py::test_every_script_ci_runs_is_type_checked
```

Plus `pyright --pythonpath .venv/bin/python` clean with `scripts` in the include list.

## Note

This is a guardrail step, not a feature. It is worth its own step rather than a rider
because fixing the surfaced errors may be more than a line, and because the check that
keeps it fixed is the part that matters.
