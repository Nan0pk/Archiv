# S08 — `archiv model calibrate`: measure the workload and the remote model

**Phase A** · depends on: S07

## Purpose

Produce a durable, auditable measurement of what one grounded question actually costs in
tokens and time, and how well the stand-in model performs on the project's own quality
gates. This is the input to S09's local-time prediction.

## The distinction this step is built around

**Time will be predicted. Quality will only ever be measured.**

Time extrapolates because the workload is bounded (see S07) and inference latency
decomposes cleanly into prompt processing and token generation. Quality does not — and
the evidence for that is stronger and more specific than intuition suggests:

- A study of 25 models found only a **weak correlation between grounding ability and MMLU
  score**, and that instruction-tuning and RLHF matter more than model size. Two models
  differing by 3.2 points in answer accuracy differed by **29.8 points in grounding**
  ([arXiv:2311.09069](https://arxiv.org/pdf/2311.09069)). So "pick a local model with
  similar MMLU" is close to worthless as a selection heuristic for Archiv's task.
- Citation fidelity specifically collapses on smaller open models. On ALCE's ASQA task,
  citation recall ran 73.6 for a hosted model, 38.4 for a 13B chat model and 10.6 for a
  13B base model ([EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398.pdf)). Those
  magnitudes are dated — contemporary 7–9B instruct models are much better — but the
  mechanism holds: attribution is a *learned behaviour*, not a by-product of capability.
- The benchmarks themselves are noisy enough to invalidate fine-grained comparison: an
  estimated **6.49% of MMLU questions contain errors**
  ([arXiv:2406.04127](https://arxiv.org/html/2406.04127v3)), and Arena Elo is upward-biased
  by selective reporting ([arXiv:2504.20879](https://arxiv.org/html/2504.20879v1)).

So inventing a quality scaling factor would be precisely the category of error this plan
exists to correct. Measure it directly instead, using machinery the project already has.

## Reuse, do not rebuild

`scripts/field_trial/` is the harness. It already:

- loads and validates a frozen benchmark of ≥20 questions
  (`scripts/field_trial/common.py::load_benchmark`);
- records `duration_ms` per question and `median_question_duration_ms`
  (`runner.py:143`, `:397-398`);
- scores required-source recall, citation integrity, answer quality and source
  navigation (`scoring.py`);
- redacts through a `PRIVATE_KEYS` allowlist so results are public-safe
  (`common.py`);
- has a determinism harness (`FIXED_TIME`, `_normalize_zip`).

Extend it. Do not write a parallel benchmark.

## Capability declaration

```yaml
name: model-calibration
purpose: Record a workload fingerprint and measured model performance for one adapter.
input_schema: benchmarks/field_trial/benchmark.json (schema_version "1")
output_schema: calibration.json — see shape below
reads: the frozen benchmark; config/model.json; runs/ask/*
writes: a calibration artefact; no product state
forbidden_paths: originals/**, derived/**, indexes/**
network_policy: one remote adapter host, only when the archive is marked for evaluation
timeout_policy: inherited per question
evidence_produced: calibration.json
validator: tests/test_model_calibration.py
```

## What `calibration.json` must contain

Follow `benchmarks/field_trial/public-results.json` — it is the house shape for a
measured result and it is good. Specifically keep:

- `schema_version`, and an id;
- the **provenance triple** that makes a number auditable: the head SHA, and where the
  measurement ran;
- **honest-negative fields.** `public-results.json` records a blocked cell as
  `{"status": "externally_blocked", "reason": "…"}` rather than omitting or faking it.
  A calibration run with no local model available must say exactly that.

New content specific to this step:

- **Workload fingerprint** (model-independent): per question and as a distribution —
  `prompt_tokens`, `completion_tokens`, `retrieval_ms`. Plus `evidence_limit`. This is
  the part that stays valid when the model changes, and it is what S09 predicts from.
- **Measured model row**: adapter, provenance, model name, `prefill_tokens_per_second`,
  `decode_tokens_per_second`, time-to-first-token, wall-clock per question, and total
  cost from S07.
- **Measured quality gates**, taken from the existing scorer, not re-derived: required-
  source recall at the evidence limit, citation validity, count of fabricated
  identifiers, and honest-refusal rate on the benchmark's negative questions.

## Rules

- Every number carries a label: `measured` or `estimated`. In this step everything is
  `measured` — `estimated` arrives in S09.
- The artefact must survive the existing redaction allowlist. No question text, no
  document content, no source names.
- Nothing derived from the model may be reported as a quality *prediction* for any other
  model. If a reader could mistake a number for a forecast, label it.

## Note on where the artefact lives

`.gitignore` blocks `field-trial-artifacts/` and `.archiv-field-trial/`. A calibration
run against a *private* archive must never be committed. A calibration run against the
public frozen fixture is publishable after redaction — same rule
`docs/public-repository-policy.md` already applies to benchmark summaries. Decide which
this is and put it in the right place.
