# S16C — Enforce Excel processing limits across library calls

**Phase C** · depends on: S16B

This is a stub to expand before implementation. The S16 review measured a 210 KB
workbook taking 383 seconds because repeated sheet references made openpyxl repeat
expensive work. Existing Archiv cell and XML budgets do not count work inside that
library. The declared `MAX_TIMEOUT_SECONDS` is not an enforced ingestion deadline.

Define and enforce a processing budget that covers the complete workbook read,
including library calls and repeated references. Preserve normal large-workbook
behavior, source integrity, deterministic failure evidence and cleanup. Budget expiry
must never leave a successful ingestion or a partial searchable result. Decide the
mechanism and limits from generated measurements when expanding this step; do not
claim a wall-clock deadline merely from loop counters.

Start with `src/archiv/ingestion/normalize_xlsx.py`, `src/archiv/ingestion/limits.py`
and the ingestion preparation path. Do not raise global document limits to accommodate
one reader. See `docs/known-issues.md` for the original measurements.
