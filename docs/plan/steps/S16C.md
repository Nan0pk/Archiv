# S16C — Enforce Excel processing limits across library calls

**Phase C** · depends on: S16B

## Why this step exists

The S16 review measured a 210 KB
workbook taking 383 seconds because repeated sheet references made openpyxl repeat
expensive work. Existing Archiv cell and XML budgets do not count work inside that
library. The declared `MAX_TIMEOUT_SECONDS` is not an enforced ingestion deadline.

## Capability declaration

```yaml
name: bounded-xlsx-processing
purpose: Stop runaway workbook parsing, including work inside third-party library calls.
input_schema: existing bounded XLSX input and normalization metadata
output_schema: existing NormalizedDocument or an explicit parsing/resource failure
reads: the input workbook and installed Python packages
writes: anonymous temporary response/diagnostic files; normal derived evidence only after success
forbidden_paths: originals/**, config/**; the worker must not store originals or mutate the input
network_policy: no new network operations; formulas, links and macros remain inert
timeout_policy: >
  One disposable Python child per workbook. The parent waits at most the existing
  MAX_TIMEOUT_SECONDS (60 seconds), then kills and reaps the child. This covers process
  startup, XML scanning, workbook loading, iteration and response serialization.
  The POSIX child uses the existing 60 CPU-second and 1 GiB address-space limits.
  A response-file ceiling of 128 MiB matches the existing expanded-input ceiling;
  the parent checks it before decoding. Existing XML and cell budgets still apply.
evidence_produced: generated normal-workbook, repeated-reference, deadline and storage-failure tests
validator: tests/test_xlsx_processing_limits.py and existing Office/ingestion/format tests
```

## Decisions and measurements

- Use a fresh Python subprocess, not a timer checked between cells: a timer cannot
  interrupt `load_workbook`. Do not fork the application's potentially threaded state
  or use pickle to transfer a document-derived object back to the parent.
- Transfer a bounded JSON request and response. The child parses only; the parent keeps
  the existing responsibility for storage and failure recording. Temporary files close
  on success, error and timeout. Do not create a new archive for rejected input.
- Reject repeated worksheet-part references before openpyxl loads the workbook. Normal
  spreadsheet applications give distinct worksheets distinct parts; an unusual workbook
  reusing one part is refused explicitly rather than multiplying expensive library work.
  This restriction does not apply to repeated chart/drawing references already cached.
- Preserve XML/position checks and recovery of incorrect dimensions. Unit tests that
  inspect parser calls run the internal reader directly; public ingestion tests run
  the real child process. Tests must not quietly lose their instrumentation across it.
- On baseline `7dca348`, generated 1,000- and 10,000-cell workbooks completed in 0.989
  and 0.533 seconds respectively, including a fresh Python invocation. A generated
  984,542-byte workbook listing one worksheet 50 times with 40,000 merged ranges was
  still running at the external 3-second cutoff and was killed. All source hashes
  remained unchanged. These are measurements of this machine, not speed guarantees.
- Keep the existing 60-second deadline rather than deriving a new global ceiling from
  those timings. Ordinary-workbook tests verify the isolated reader remains usable.
- After the change, the same generated cases completed in 0.781 seconds (1,000 cells),
  0.982 seconds (10,000 cells) and were refused in 0.824 seconds (the 984,542-byte
  repeated-reference workbook). The refusal happens before openpyxl is imported for the
  workbook, and source hashes were unchanged in all three runs.
- Raise the Excel extractor version from 3 to 4, because a workbook that used to be
  accepted can now be refused and every worksheet read now crosses the worker boundary.
  Old derivatives are marked stale and rebuilt with `archiv rebuild-derived`.
- This is process/resource isolation, not a complete hostile-code sandbox. The worker
  receives the application's environment and installed code; it adds no network calls.

Start with `src/archiv/ingestion/normalize_xlsx.py`, `src/archiv/ingestion/limits.py`
and the ingestion preparation path. Do not raise global document limits to accommodate
one reader. See `docs/known-issues.md` for the original measurements.
