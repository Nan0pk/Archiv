# S16A — Reject XML declarations regardless of encoding

**Phase C** · depends on: S16

## Why this step exists

The OpenDocument and InPage mapping readers searched raw bytes for `<!DOCTYPE` and
`<!ENTITY`. UTF-16 encodes those strings differently, so declarations passed the check
and the XML parser expanded their entities. Word and Excel already used an encoding-aware
Expat scan. This step shares that scan and applies it to the two affected readers.

## Capability declaration

```yaml
name: encoding-independent-xml-declaration-refusal
purpose: Refuse DTD and entity declarations before building a tree or expanding an entity.
input_schema: XML bytes already bounded by the calling document or mapping reader
output_schema: no value on success; a typed error for declarations or malformed XML
reads: the supplied bytes only
writes: none; existing ingestion failure recording remains the caller's responsibility
forbidden_paths: originals/**, config/**; source files are never modified
network_policy: none; external DTDs are refused without fetching them
timeout_policy: one Expat scan over the input; caller byte, node and entry limits remain
evidence_produced: generated fixtures in tests/test_xml_declarations.py
validator: the pytest acceptance targets below, plus existing Office and InPage tests
```

## Scope and compatibility

- Use one shared checker from OpenDocument, InPage mapping XML, Word and Excel. Preserve
  caller error categories and the distinction between a declaration and non-XML package
  data; Excel must still accept binary members such as images.
- Reject DOCTYPEs with internal or external subsets, nested entity declarations, and
  empty DOCTYPEs. The parser stops at the start of the declaration.
- Keep ordinary XML encoding declarations, Unicode, predefined entities, comments and
  CDATA valid. Declaration-looking text inside a comment or CDATA is literal text.
- Exercise UTF-8 and both UTF-16 byte orders, with and without the UTF-16 BOM.
- Through actual ODT ingestion, check both content and manifest parts and prove that
  rejection leaves source bytes unchanged and creates no original or derived object.
- Keep existing byte, node and mapping-entry limits. This does not add a general parser
  deadline, revalidate old archives, or change extraction schemas or locators.
- Fixtures are generated in temporary directories. No third-party documents or new
  dependencies are required.

module and the three existing Office regression tests below. This requires every
encoding/declaration case to pass; the status tool's literal node-ID matcher does not
aggregate parameterized cases. Initialize the development environment before running it.
