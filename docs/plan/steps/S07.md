# S07 — Pre-flight token count, projected cost, and a hard spend ceiling

**Phase A** · depends on: S04

## Purpose

A remote model costs money per call. Make the cost visible before it is incurred, and
make runaway spend structurally impossible rather than a matter of remembering.

This also produces the token measurements S08 needs, so it comes before calibration.

## Capability declaration

```yaml
name: remote-evaluation-cost-control
purpose: Count tokens and project cost before a remote call; refuse to exceed a ceiling.
input_schema: the assembled grounding prompt; a configured price table and ceiling
output_schema: {prompt_tokens, projected_cost, cumulative_spend, ceiling}
reads: config/model.json; config/evaluation.json
writes: a cumulative spend record under config/ or runs/
forbidden_paths: originals/**, derived/**
network_policy: token counting must not require a network call where the provider offers
  a local tokenizer; if it does, it is part of the same single configured host
timeout_policy: inherited
evidence_produced: per-run token and cost record in the run evidence
validator: tests/test_remote_evaluation_cost.py
```

## Why this is tractable here

The workload is bounded by construction. `archiv ask --max-sources` is validated to
1–50 with a default of 8 (`user_cli.py:480-566`), and `build_grounding_prompt`
(`grounding.py:20-79`) assembles a fixed instruction block plus one entry per citation.
So prompt size is predictable, which is what makes both cost projection and the S09
latency prediction defensible rather than hand-waving.

## What to build

- Count prompt tokens **before** the request. Prefer the provider's own tokenizer or
  count endpoint; never estimate from character length, and never use a tokenizer from a
  different model family.
- A price table in configuration — input and output rate per million tokens — with the
  date it was recorded, because published prices change.
- A projected cost shown before a remote run, and a **hard ceiling** checked before any
  network activity. Exceeding it is a refusal, not a warning.
- A cumulative spend record per archive, so the ceiling is meaningful across runs rather
  than per-call.

## Design note

The refusal must happen before the request is sent, not after the response is billed. Put
the check on the same side of the boundary as `check_evaluation_opt_in` from S03 — both
are pre-flight policy gates and should read as one gate, not two scattered ones.

## Acceptance

```
tests/test_remote_evaluation_cost.py::test_prompt_tokens_are_counted_before_any_request
tests/test_remote_evaluation_cost.py::test_run_exceeding_the_ceiling_is_refused_before_the_network_call
tests/test_remote_evaluation_cost.py::test_cumulative_spend_is_recorded_per_archive
tests/test_remote_evaluation_cost.py::test_projected_cost_is_shown_before_a_remote_run
```

The second test is the one that matters: assert the transport was never invoked, not
merely that an error was returned.
