# S02 — Add provenance to ModelConfig and branch dispatch on the adapter literal

**Phase A** · depends on: S01

## Purpose

Make the model adapter dispatch explicit, and add the field that will carry model origin
through every downstream artefact. No new adapter is added here.

## The actual bug this fixes

Both the validator and the factory branch on `disabled` and treat **everything else** as
loopback:

```python
# model_adapter.py:31-51 (validator)
if self.adapter == "disabled":
    ...
    return self
# …everything below is the loopback rule set, reached by fallthrough

# model_adapter.py:135-138 (factory)
if config.adapter == "disabled":
    return DisabledModelAdapter()
return OpenAICompatibleLoopbackAdapter(config)
```

Adding a third adapter value to the `Literal` without changing this would silently
subject a remote adapter to the loopback URL rules — or, if those rules were relaxed to
accommodate it, would silently exempt the *local* adapter from them too. Either way the
privacy boundary stops being enforced by construction. Fix the control flow first, in its
own reviewable diff, before S04 needs it.

## What to change

`src/archiv/model_adapter.py`:

- Add `provenance: Literal["local-loopback", "remote-evaluation"]` to `ModelConfig`,
  **derived from `adapter` in the validator, not accepted from input.** `ModelConfig`
  subclasses `StrictModel` (`contracts.py:29-32`, `extra="forbid"`), so a caller passing
  a conflicting value must be rejected rather than ignored.
- Restructure `validate_adapter_fields` into an explicit branch per adapter literal, with
  a final `raise` for an unhandled value rather than a fallthrough.
- Restructure `build_model_adapter` the same way.

## Forward-compatibility note

`extra="forbid"` cuts both ways here:

- An **existing** `config/model.json` written before this change has no `provenance` key,
  and loads fine because the field has a default. Test this explicitly.
- A **new** `config/model.json` written after this change will be *rejected* by an older
  Archiv build. `config/` is in `DURABLE_DIRECTORIES` (`archive.py:25`) and travels in
  backups and exports, so this is a real downgrade consideration. `docs/architecture.md`
  already states Archiv never performs an in-place downgrade, so this is consistent — but
  note it in the PR and consider whether `docs/known-issues.md` should record it.
