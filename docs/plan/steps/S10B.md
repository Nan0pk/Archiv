# S10B — Refuse unsafe image duplicate claims

**Phase B** (Stop the tool overclaiming) · depends on: S10A

> This step is deliberately narrow. The owner chose to rebuild duplicate detection with
> methods matched to each job. Before any of those larger replacements are built, the
> known-dangerous command must stop presenting the current colour-and-edge score as proof
> that files are duplicates.

## Why this step exists

Step S10A measured unrelated document pages receiving the same duplicate score as real
copies. The owner chose option 3 on 2026-09-12. The decision record requires the existing
`archiv images duplicates` surface to refuse until a replacement method has passed its own
acceptance measurements.

Leaving the command live while deeper work proceeds is not acceptable: this is the surface
whose output can lead a user to delete unrelated files.

## Capability declaration

```yaml
name: image-duplicates-safe-refusal
purpose: Prevent Archiv from making a duplicate claim with a method already shown to be unreliable.
input_schema: the existing archiv images duplicates command arguments
output_schema: a clear refusal explaining that image duplicate detection is being rebuilt
reads: image index metadata only as needed to enter the command
writes: nothing
forbidden_paths: originals/**, derived/**
network_policy: none
timeout_policy: n/a
evidence_produced: regression tests showing the old duplicate grouping path cannot emit groups
validator: tests/test_image_duplicates.py
```

## What to do

- Make `archiv images duplicates` return a clear, non-success duplicate-detection outcome
  instead of calling the current colour-and-edge grouping method.
- State in plain language that the old method could not safely distinguish some unrelated
  content and is being replaced.
- Do not disable Archiv's existing exact-content duplicate accounting during ingestion.
- Do not remove `find-similar`; it remains a separate image-similarity surface and must not
  be reused as duplicate proof.
- Do not implement perceptual hashing or document comparison in this step.

## Acceptance

```
tests/test_image_duplicates.py::test_duplicates_command_refuses_the_old_similarity_method
tests/test_image_duplicates.py::test_refusal_explains_why_no_duplicate_groups_are_reported
tests/test_image_duplicates.py::test_exact_content_duplicate_accounting_still_works
```

The first test must exercise the command with the generated unrelated-document fixtures
that previously grouped together and prove that no duplicate group can be emitted.
