# S07B — A run refused part-way through must not record itself as allowed

**Phase A** · depends on: S07A

> Filed from review of the S07A/S08 batch rather than fixed in it, because it changes
> what a run's cost record means and deserves its own tests.

## The gap

The cost decision is taken once, before the model call, and written to
`runs/ask/<id>/cost.json`. The retry layer above the call can send the same question up
to three times, and each attempt goes through the spend gate inside the adapter again.

So a question whose first attempt was allowed, and whose second is refused because that
first attempt pushed recorded spend past the ceiling, ends like this:

- `result.json` says `failed`, with the refusal as a generic model-request failure;
- `cost.json` says `"decision": "allowed"`.

The evidence therefore states the run was allowed to spend when it was stopped from
spending, and the reason it was stopped appears nowhere except inside an error string.
This is the same defect S07A fixed for a run refused up front, in the one place S07A did
not reach.

It is not a money leak — the ceiling still held, and the refusal still happened before
the second request was sent. It is an evidence defect, which in this project is the kind
that matters: somebody reading the run later is told something untrue.

## What to change

- A refusal that happens after the first attempt must reach the run's record. Either the
  decision is re-taken and re-written per attempt, or the run's ending carries the
  refusal and `cost.json` stops claiming a decision that a later attempt overturned.
- Decide, and write down, what `cost.json` means when attempts disagree: the decision for
  the run, or the decision for each attempt. One record per attempt is probably right,
  since each attempt was separately allowed or refused and separately billed.
- The run's status should be `blocked_by_policy` when the reason it ended was the ceiling,
  even if it got there part-way through. Text had already been sent by then, so the
  disclosure banner must still say so — the two are independent, and conflating them is
  how S05's banner defects happened.
