# S06 — Stamp the report path, and fix the DOCX that always claims 'disabled'

**Phase A** · depends on: S05

## Purpose

Do for `report` what S05 did for `ask` — and fix a pre-existing bug found while mapping
it.

## Read this before you start: report does not share ask's code

`archiv report` does **not** go through `run_grounded_ask`. `src/archiv/tasks.py:127-152`
re-implements the model call inline. So nothing S05 did applies here. This is the single
most likely place to assume work is finished when it is not.

## The pre-existing bug

The generated DOCX has a `Provenance` section (`reports/generator.py:162-174`) with a
`Model identity:` line. Its value comes from a `model_identity: str` parameter that
**defaults to `"disabled"`** at three signatures (`generator.py:78`, `:195`, `:225`).

Its only producer is `tasks.py:123-125`. Two other callers never pass it:

- `report_cli.py:64-76` (`archiv generate-report`)
- `mcp_tools.py:152-160` (the MCP `archiv_generate_docx` tool)

So every DOCX produced through those two paths states `Model identity: disabled`
regardless of what actually ran. That is a false provenance claim inside a document whose
whole purpose is verifiable provenance. Fix it in this step.

## Capability declaration

```yaml
name: report-provenance-stamp
purpose: Record true model origin in the report manifest and inside the generated DOCX.
input_schema: ReportManifest (schema_version "1") plus model identity and provenance
output_schema: ReportManifest with model fields; DOCX Provenance section carrying them
reads: config/model.json; runs/tasks/<id>/*
writes: outputs/**, <docx>.manifest.json, <docx>.validation.json
forbidden_paths: originals/**
network_policy: inherited from the configured adapter
timeout_policy: inherited
evidence_produced: manifest model fields; DOCX text; rendered PDF text
validator: reports/validation.py plus tests/test_remote_evaluation_provenance.py
```

## What to change

- **`ReportManifest` has no model field at all** (`report_contracts.py:30-41`). Add
  model identity and provenance. Being a `StrictModel`, this is a schema change — bump
  or document accordingly.
- Thread `model_identity` from `report_cli.py` and `mcp_tools.py`. Consider making the
  parameter required rather than defaulted, so a future caller cannot reintroduce the
  same silent lie. That is the stronger fix.
- Put the stamp in the DOCX's existing `Provenance` section. Note the validator
  constraints:
  - `validation.py:155-156` asserts `manifest.required_sections` equals
    `REQUIRED_REPORT_SECTIONS` (`report_contracts.py:11`) **exactly**;
  - `:183-185` asserts each required section name appears in the extracted DOCX text;
  - `:224-226` re-asserts it in the rendered PDF text.

  Adding a *line inside* the existing `Provenance` section needs no validator change —
  but it also gets no validator enforcement. Prefer asserting the new line explicitly in
  the report validator so a missing stamp fails the report rather than passing quietly.
- Consider `template.py:37-41` core properties, so the stamp survives inspection of the
  file's metadata outside Archiv — `docs/definition-of-done.md` requires that generated
  artefacts can be inspected outside Archiv.
