# S16B — Recover Excel cells beyond incorrect worksheet dimensions

**Phase C** · depends on: S16A

## Why this step exists

The S16 review found that a sheet declaring `A1:A1` but containing a cell at `C9`
silently loses that cell because the read-only workbook reader trusts the declared
dimensions. A smaller column bound drops cells too, even when the row bound is correct.

Recover actual cells without trusting the smaller dimension. Preserve cell coordinates,
formula/stored-value pairing, hidden markers and source hashes. Retain iteration and
memory limits when a sheet declares a very large dimension or contains sparse cells.
If recovery is impossible, refuse explicitly rather than reporting complete extraction.

Start with `src/archiv/ingestion/normalize_xlsx.py` and generated workbook fixtures in
`tests/test_ooxml_recovery.py`. Do not replace the bounded reader with an unrestricted
in-memory load. See `docs/known-issues.md` for the review evidence.

## Capability declaration

```yaml
name: recover-xlsx-cells-outside-declared-dimensions
purpose: Read stored worksheet cells even when the declared worksheet size is too small.
input_schema: an XLSX package accepted by the existing bounded validation path
output_schema: existing NormalizedDocument, cell locators and worksheet tables
reads: package XML and the two existing read-only openpyxl workbook views
writes: derived evidence through the existing ingestion path only
forbidden_paths: originals/**, config/**; source files remain byte-identical
network_policy: none; formulas and links are never executed or fetched
timeout_policy: >
  The existing XML pass records actual row and column bounds before openpyxl iterates.
  Read bounds cover both declared dimensions and actual stored cells. A rectangle larger
  than MAX_CELL_POSITIONS is refused before row allocation or iteration; the existing
  shared position budget still counts iteration, tables, links and charts.
  This is not a processing deadline; work inside library calls remains S16C.
evidence_produced: generated recovery, citation, source-integrity and limit tests
validator: pytest acceptance targets below and the existing Office/format-matrix tests
```

## Scope and compatibility

- Collect actual cell bounds while the existing XML pass reads each worksheet; do not
  add a third workbook load or an unrestricted in-memory worksheet.
- Read formula and stored-value views with identical explicit bounds. Preserve formula
  text, missing-result markers, hidden markers, merges, tables and native cell addresses.
- Support missing dimensions and omitted row/cell coordinates using the library's
  sequential numbering rules. Refuse inconsistent or unordered row/cell coordinates
  rather than silently assigning text to another location.
- Retain refusal of oversized declared dimensions. Actual sparse coordinates must not
  allocate an enormous padded row before the position limit can be checked.
- Test ingestion and search with a generated marker beyond an incorrect dimension,
  including unchanged source bytes and a citation with its real cell address.
- Rejected oversized input must create no original or derivative. In an existing archive
  it must record an ingestion failure; keep the existing behavior of not creating a new
  archive for rejected input. Keep the existing error category and limit wording.
- No automatic rebuild of old derivatives, new dependency, or change to global limits.
