# S13 — Index staleness: refresh on add, report N of M, incremental image index

**Phase B** (Stop the tool overclaiming) · depends on: S00

## Capability declaration

```yaml
name: index freshness after add
purpose: keep rebuildable image-search and entity-graph indexes synchronized with newly ingested canonical objects, and report image-index coverage honestly
input_schema: an existing Archiv archive plus files accepted by `archiv add`
output_schema: the normal add result; an image index containing every indexable canonical image; a rebuilt entity graph reflecting the current archive; and image status that reports indexed images against the archive's total image-object count
reads:
  - canonical object metadata and originals under the selected archive
  - the existing image index when it is compatible with the active embedder
  - current entity-graph inputs
writes:
  - the replaceable image index under indexes/
  - the replaceable entity graph under indexes/
  - the normal ingestion/search-index state already written by `archiv add`
forbidden_paths:
  - canonical originals
  - source files supplied to `archiv add`
  - configuration unrelated to these rebuildable indexes
network_policy: no network access; image embeddings use only the already-installed local embedder and may not download models or other artifacts
timeout_policy: use the existing bounded ingestion and processor policies; this step adds no new timeout or resource-budget exception
evidence_produced: the declared S13 pytest acceptance tests, including generated image fixtures and observable index/graph/status state
validator: the three S13 pytest targets in docs/plan/queue.json plus the repository-required formatting, lint, type, full-test, and doctor checks
```

## Required behaviour

After a successful `archiv add`, Archiv refreshes the image index and entity graph before reporting the add operation complete. The text search index keeps its existing automatic refresh. A failed derived-index refresh must not damage canonical originals; derived indexes remain rebuildable.

Image-index refresh is incremental. Existing rows made by the same active embedder are retained without re-embedding their originals, newly indexable image objects are embedded and inserted, and rows whose canonical image object no longer exists are removed. If the existing index is missing or incompatible with the active embedder's model or dimensions, Archiv may rebuild it rather than reuse incompatible rows.

`archiv images status` must compare the number of indexed rows with the number of canonical image objects in the archive. Human output states the indexed and total counts. JSON output exposes both counts. It may report the index as ready only when those counts agree; a stale index must be labelled stale rather than ready. The total is an object count, not an ingestion count, so exact-content duplicate ingestions do not inflate it.

The entity graph does not need an incremental algorithm in this step. Refreshing it after add may use its existing rebuild path. This step changes freshness, not graph semantics.

## Non-goals and boundaries

- Do not change the image similarity method, duplicate-detection refusal, measured match floor, or S10A/S10B decisions.
- Do not weaken the loopback model boundary or add network access.
- Do not download model weights or other artifacts at runtime.
- Do not alter canonical originals or make a derived index authoritative data.
- Do not add a dependency; if implementation unexpectedly needs one, stop and re-plan because dependencies must remain optional extras.
- Do not make the entity graph incremental in S13.

## Acceptance

The provisional targets were checked against the capability above and remain the acceptance contract, so `queue.json` does not change:

```
tests/test_index_freshness.py::test_add_refreshes_the_image_index_and_graph
tests/test_index_freshness.py::test_status_reports_indexed_count_against_object_count
tests/test_index_freshness.py::test_image_index_update_is_incremental
```

The tests generate their own fixtures. The first proves a successful add leaves both derived indexes current. The second proves status cannot call a partial image index ready and reports indexed objects against total canonical image objects. The third uses an instrumented embedder to prove an already-indexed compatible image is not embedded again when a new image is added.
