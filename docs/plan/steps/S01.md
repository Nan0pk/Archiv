# S01 — Pin the loopback privacy boundary with tests before changing anything

**Phase A** · depends on: S00

## Purpose

Lock the current behaviour of the loopback-only model boundary into tests **before** any
work that touches it. Phase A adds a remote adapter; this step makes it impossible to
weaken the local one by accident along the way.

Every test in this step passes against today's code. That is the point: they are a
tripwire, not a to-do list.

## Capability declaration

```yaml
name: model-boundary-regression
purpose: Assert the loopback endpoint policy rejects everything it currently rejects.
input_schema: none (unit tests over ModelConfig)
output_schema: none
reads: src/archiv/model_adapter.py
writes: tests/test_model_boundary.py
forbidden_paths: src/archiv/** — this step adds no product code at all
network_policy: none; no test may open a socket
timeout_policy: unit-test speed
evidence_produced: tests/test_model_boundary.py
validator: pytest
```

## What the boundary currently guarantees

From `src/archiv/model_adapter.py:29-51`, `ModelConfig.validate_adapter_fields` rejects:

| Input | Line | Message |
|---|---|---|
| `https://…` | :39-40 | must use plain HTTP on loopback |
| a non-loopback host | :41-42 | must resolve explicitly to loopback |
| userinfo, query or fragment | :43-46 | must not contain credentials, query, or fragment |
| a path other than `""` or `/` | :47-48 | must be a server root without an API path |
| `api_key_env` that is not an identifier | :49-50 | must be a valid environment-variable name |
| `disabled` plus any of endpoint/model/key | :31-34 | disabled adapter must not declare … |
| a non-disabled adapter missing endpoint or model | :36-37 | loopback adapter requires endpoint and model |

And `DisabledModelAdapter.complete` (`:60-66`) raises
`"model use is disabled; Archiv will not select a hidden fallback"`.

## What to write

One new file, `tests/test_model_boundary.py`, asserting each row above. Follow house
style: `from __future__ import annotations`, `-> None` on every test, and
`pytest.raises(ValidationError)` with a `match=` on a substring of the user-visible
reason — the existing idiom in `tests/test_capability_expansion_m1.py:52-73` asserts both
the exception type *and* the message, and does so at two layers.

Cover at minimum: `https`, `http://example.com`, `http://10.0.0.5`,
`http://user:pw@127.0.0.1`, `http://127.0.0.1/?x=1`, `http://127.0.0.1#frag`,
`http://127.0.0.1/v1`, and the three loopback spellings that must *pass*
(`127.0.0.1`, `localhost`, `[::1]`).

## Why this is a separate step

It is small, it is pure test code, it cannot break anything, and it must exist before
S02 changes the validator's control flow. Merging it separately means the diff that
touches the boundary arrives with its safety net already on `main`.
